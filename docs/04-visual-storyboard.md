# 04 — Visualization & CIO/C-Level Slide Briefs

This file preserves decisions made during iterative image reviews. AI-generated visual drafts are **design references**, not verified data sources.

## Global visual identity
- Format: **16:9**, **black background** with white text and limited **critical red**
- Readable in **5–10 seconds** for executive summaries; hierarchy number → label → one-line consequence
- One clear main point per slide, minimal decoration, avoid walls of text
- Red = loop / rework / bottleneck **only if evidence supports it**; neutral steps slate/gray
- Distinguish **confirmed data** from **illustrative links**, `reported` time and `unverified` criticality scores
- English-only version of the presentation preferred; Thai original/source terms remain in reference docs

## Visual A — Executive one-page summary (6 topics)
1. **Timing**: `7–10 months` **reported end-to-end per Strategy Project**, confirmation pending
2. **Actions**: `199 catalog entries`; `196 Tower=R`
3. **Deliverables**: `195 named deliverable entries` (not documents/files); taxonomy 6 **proposed** groups
4. **Rework**: `156 Loop=Y` out of 199 catalog rows (not 156 completed loops)
5. **Development concentration**: Stage 8 `100 rows / 87 flagged`
6. **Go-live and support**: Stages 11–12 `14 rows`

Tagline: **The delivery process consumes Tower capacity before, during and after SDLC.**

## Visual B — As-Is 3-layer diagram
- Layer 1: **7 workstream categories**
- Layer 2: **12 stages** (with 6.1 / 6.2 branching rather than double-counting)
- Layer 3: actions, deliverables, loop flag/count range, estimated days per cycle, owner/RACI, pain points
- One consistent set of red return arrows with source/destination; no decorative duplicate arrows

## Visual C — Snakes & Ladders (linear)
- The normal path is a **light/white/blue forward road**
- Backtracking paths are **large, conspicuous red curves**
- Stage 8 is visually most prominent (100 catalog rows / 87 loop flags)
- Rework labels: BRD revision, budget re-estimation, test/retest, rejected readiness package, post-live incident
- A green ladder/fast track is a **metaphor only** and must not suggest a real bypass without confirmation
- Bottom Key Takeaway is one sentence

## Visual D — Monopoly-style perimeter board (preferred later)
- All **12 stage positions around the board perimeter**, with `6.1 / 6.2` as alternative tiles/branch
- The **center** is the trapped `REWORK LOOP`: hourglass, pawn stuck, papers returning, spinning arrows
- Add no outside KPI panels; keep attention on each Stage's Action(s) and where work is sent back
- Center copy: **“Work keeps coming back for revision — progress stalls.”**
- Each stage contains **2–3 true action examples**, not invented stage names
- Qualitative temperature `Low/Medium/High/Critical` is **draft visual language only**, not derived from measured risk; if displayed, label `illustrative` and confirm with process owners
- Avoid presenting 12 fabricated per-stage counts as authoritative. Source ledger numbers are in [process table](02-as-is-process.md).

## Visual integrity checks
- Exact naming: Stage 8 is `Project Development (SDLC)`; SRA is a significant **sub-workstream**, not the official name of Stage 8
- Official Stage 9 = Quality Approval; Stage 10 = Technical Readiness Approval; Stage 11 = Go-live and Monitoring; Stage 12 = After Go-live Support
- Typical `7–10 months` should not be translated as a calculated sum of sequential rows
- Avoid invented percentages such as `Overall efficiency = 62%`
- Note that prior image variants sometimes mislabeled stage IDs, invented action counts, or rendered Thai/English incompletely
